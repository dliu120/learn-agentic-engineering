<ConceptCard title="Three MCP roles" tag="architecture">

- **Host** — the AI application that owns the user experience, consent, and context.
- **Client** — one connector inside the host for one server connection.
- **Server** — a separate program that exposes capabilities and context.

</ConceptCard>

MCP standardizes the connection. It does not remove the need for permission checks, validation, timeouts, or product-specific UX.

## Tools, resources, and prompts

| Primitive | Who chooses it? | Example |
|---|---|---|
| **Tool** | Model | Create an issue |
| **Resource** | Application | Attach a file or database record |
| **Prompt** | User | Run a named review template |

The host may add stronger controls. A payment tool can require confirmation even when the model
selects it.

<DeepDive title="Local and remote transports">

Local servers commonly use **stdio**: the host launches a subprocess and exchanges messages over
standard input and output. Remote servers commonly use **Streamable HTTP** and need network
authentication, TLS, tenancy checks, and revocation.

Clients can also expose capabilities back to servers. In the 2026-07-28 protocol, **elicitation**
lets a server request additional user input through the host. Keep that flow visible to the user;
it is not permission for a server to open an invisible side channel.

</DeepDive>
